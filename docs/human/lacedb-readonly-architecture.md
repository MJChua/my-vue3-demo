# 寵物資料架構說明

這份文件用簡化方式說明目前寵物資料如何設計。

## 目前階段

目前專案是「唯讀」寵物瀏覽：

- 使用者可以瀏覽寵物內容。
- 寵物資料來自公開 API。
- 暫時不提供會員上傳與資料寫入。

## 未來規劃

未來會加入社群上傳功能，資料關係會變成：

- 一位使用者可以擁有多筆寵物資料。
- 一筆寵物資料可以記錄擁有者。
- 可支援共同擁有者等關係。

## 主要資料

### 使用者

會記錄：

- 使用者 ID。
- 顯示名稱。
- 頭像。
- 擁有的寵物 ID 清單。
- 建立與更新時間。

### 寵物

會記錄：

- 寵物 ID。
- 名稱。
- 類別，例如狗、貓、特殊寵物。
- 圖片。
- 簡介。
- 標籤。
- 擁有者。
- 建立與更新時間。

### 使用者與寵物關聯

未來若要支援共同擁有者，會使用關聯資料記錄使用者與寵物之間的角色。

## 目前讀取方式

1. 依照類別取得寵物資料。
2. 將遠端 API 回傳整理成專案內部格式。
3. 提供首頁使用，例如全部、狗、貓、特殊寵物篩選。

## 設計原因

現在先保留未來需要的關聯欄位，可以讓之後加入上傳功能時少做大型資料遷移。
